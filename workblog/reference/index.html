    Reference¶

    Last updated: October 2026.

    In short

    Look-up material: the run configuration behind the numbers, the settings of each lake, where the code for each part lives, a glossary, and frequent questions. Every configuration key is described in Run configuration.

    Run configuration behind the numbers¶

    The operational setup is called simplified_final. The numbers on these pages were made with the code at commit 20564a9, where its σ values are in args/run_enkf.json.

    • Ensemble: 20 members, generated by AR(1) forcing perturbation on wind U, wind V and solar radiation.
    • Period: 2025 calendar year, daily assimilation at a per-lake night-time hour (23Z–06Z).
    • Engines: native Python EnKF and OpenDA, configured from identical inputs, perturbed forcings, warmup and observation series, so that residual differences are the algorithm alone.
    • Observations: causally filtered below 4 m with a per-lake seiche-derived window, thinned to a per-lake target vertical grid, retained at the assimilation hour.
    • Observation error: fixed per lake and season (mixed / stratified, stratified = May to October); Ägeri one value for the whole year.
    • Scoring: RMSE against hourly observations unless stated otherwise; the surface-only comparison and the CTD check of adaptive σ are scored against CTD casts.

    Glossary¶

    Term Meaning
    Free run The model run without assimilation, from the same start; the baseline every gain is measured against.
    Analysis The state after the filter has corrected it with an observation.
    Ensemble, member The N perturbed copies of the model run in parallel; one copy is a member.
    Spread The standard deviation across the members: the model's own uncertainty.
    Innovation Observation minus model forecast at the observed depth, before the correction.
    Increment, correction How much the analysis changes the state.
    σ (observation error) The uncertainty handed to the filter for each observation. Here a representativeness error, not instrument error.
    Representativeness error What the model cannot reproduce: variability a 1D column cannot produce (e.g. internal waves) and the difference between a point measurement and a lake-wide column.
    Uncertainty budget The total uncertainty the filter expects, √(spread² + σ²), against the actual model–observation gap.
    NIS Normalised innovation squared, d² / (spread² + σ²). 1 = consistent, below 1 over-cautious, above 1 over-confident.
    Calibration (of the filter) How close NIS is to 1. Not the same as accuracy.
    Mixed / stratified season November–April / May–October.
    Seiche filtering Causal trailing average below 4 m, over one internal-seiche period, removing thermocline displacement the 1D model cannot reproduce.
    Localization Forcing small, probably spurious correlations between distant depths to zero in the update.
    Under-dispersion The ensemble spread is smaller than the actual error.
    Native / OpenDA engine The project's own Python implementation, and the setup running the same filter through OpenDA.

    FAQ¶

    Why only 20 members? Cost, in the operational chain. Twenty is what we can afford daily across seven lakes. It is a real limitation, not a choice we would defend on statistical grounds.

    Isn't filtering the observations just throwing away real signal? Yes, and deliberately. The sensor is right and the signal is real. But it is an internal-wave displacement that a 1D column cannot produce, so feeding it to the filter asks the model to reproduce something it structurally cannot.

    Why does better calibration not give better accuracy? Calibration means the filter's stated uncertainty matches the innovations it sees. That is self-consistency. It says nothing about whether the correction goes in the right direction at the right depth.

    What is the single biggest limitation? Ensemble under-dispersion. We generate spread only at the surface, through three forcing variables, and it reaches depth only by mixing (Open problems).
